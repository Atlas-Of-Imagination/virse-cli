# 检查与迭代

先取得并查看真实产物，再判断是否满足用途。任务状态成功只能证明生成流程完成；缩略图可判断整体，文字、身份、边缘和细小结构需要足够清晰的预览或原件。无法查看时说明未验证的部分，不把模型自述、文件存在或 API 成功写成视觉验收通过。

## 按目标看图

先把图放到真实使用尺度判断主目标，再放大看关键局部。缩小后关注点丢失，优先改层级；只有放大才可见、又不影响用途的纹理瑕疵，不应压过整体问题。用户要粗粝速写，就不按商业修图检查每个边缘；用户要商品图，就重视真实结构、标签和材质。

| 检查顺序按任务选取 | 看什么 | 发现问题后先判断 |
| --- | --- | --- |
| 内容与保留项 | 主体、数量、动作、关系、原图特征是否正确 | 是需求漏写、歧义、模型能力还是参考冲突？ |
| 整体阅读 | 焦点、构图、主体占比、必要文字、交付裁切 | 调容器比例、移动主体、降低干扰还是重新排版？ |
| 结构与动作 | 轮廓、关键部件、连接、透视、受力、接触 | 局部可修还是需要更换姿态或结构参考？ |
| 光色与媒介 | 明暗、材质、相对色彩、边缘与笔触是否服务表达 | 缺的是光线依据、材质特征还是语言相互抵消？ |
| 文件 | 实际宽高、格式、透明度、数量及可用文件 | 是生成内容问题还是导出与处理问题？ |

先描述观察，再给原因判断：“标题在手机尺度读不清，因为字号小且背景纹理穿过笔画”，比“质感不够高级”更可执行。原因不确定就保留为假设，通过小范围对照验证；不要声称从图片看出了模型的内部机制。

## 选最小有效修正

找到最影响目标、又能实际改变的因素。主体占比不合适，改取景或扩图；人物正确但手部错，评估局部修复；品牌文案反复错，改用准确排版；复杂多人动作混乱，补清晰姿态参考、拆场景或减少相互作用须符合用户意图。

每次修正明确“这次改变什么、哪些已认可内容保留”。可一起调整同一原因下紧密关联的内容，例如新背景的光向与阴影；不要为追求形式一次只改一个词。需要理解影响时减少变量，避免换完所有设置后把改善归给其中一项。

重复失败先检查输入是否真正进入模型、操作是否支持、蒙版是否正确、目标是否互相冲突。继续补同义限制没有新依据时，应换方法：裁切或合成、局部编辑、结构参考、适配模型，或就目标取舍与用户确认。消耗型重试始终受已有授权、费用与数量范围约束，不无限生成。

交付对应用户请求：只要 prompt 就给 prompt；要诊断就给主要问题与修正方向；要图片就给实际产物和必要的未达项。用户要求对比时说明实质差异，不把尚未生成的候选描述成已验证效果。

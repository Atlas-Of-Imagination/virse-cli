# 构建个人或企业资产库

## 汇集迁入

结合用户用途和当前可读材料，主动推荐值得收录的来源、素材与组织方案。来源可含指定的本地目录、其他平台、Virse 目录与项目画布；可主动寻找补充素材，范围先与用户敲定。已给信息沿用，只补问影响结果的缺口；未连接或未读过的资料明确标为待盘点。

迁入前敲定用途、来源与收录范围、目标个人或团队空间及落点和可见范围，以及分类命名、成套组织与取用方式。说明从哪里取什么、怎样迁入，给出贴合真实素材的建议供用户调整；已有确认或明确自主授权的范围沿用。方案确认后连续完成，新增来源或关键变化再对齐。

本地指定且有权读取的目录可直接盘点。其他平台先发现宿主现有的 MCP、连接器或 CLI 能力；缺连接或权限时说明要访问什么，引导用户按对应服务的实际流程连接、登录或授权后继续。已有授权不重做，授权仅覆盖约定范围；可看预览不等于可取得原件，不以预览冒充原件。

按实际来源和动作选读：定位 Virse 资源时读[查找与读取](browse.md)，单文件上传读[上传与替换](upload-replace.md)，目录批量导入读[导入批次](import-batches.md)。其他平台先按实际授权能力取得导出文件，再导入当前支持的格式。需要转换时确认保留形式，保留原件与来源关系，不能把位图说成原生可编辑工程。默认保留来源材料；批量导入保留进度与逐项结果，不把跳过、失败或未确认项算作已入库。

Virse 同组织复制、画布媒体另存按[整理与归档](organize.md)处理；跨组织素材按已授权可取得的内容重新导入，不把切换组织或同组织 move/copy 当跨组织原件迁移。来源、目标资源和新身份分别记录。

## 按使用方式整理成库

将分类、命名和常用素材组合放在同一轮整理中。依据项目、用途或用户取用习惯提出方案，已有规则沿用。每套的内容、用途与取用方法按确认方案在库内保存，可由清晰目录命名、支持的文档或画布索引承载，并对应实际资源，不能只留在聊天。可用稳定位置与已确认的收藏置顶方式组织，不把“素材包”假设成新的平台资源类型，也不把本地 TXT、JSON 清单说成已入库。

按[整理与归档](organize.md)执行已确认的目录与资源操作。需要重整已有库时进入[资产库整理](organize-library.md)，保留其状态记录选择与详细方案确认；仅向新库导入，不强制展开旧库撤回流程。移动或落点影响可见范围时，核对实际结果；需要调整规则再按 `virse-sharing` 处理，“团队库”不自动授权扩大访问。

日常保留按项查看和取用的入口。用户需要下载交付时再按文件交付（`virse-base/references/contracts/delivery.md`）选择资源打包，不能把 ZIP 当成库已构建或全部已交付，也不假定文件夹会递归打包。

完成后读回真实目录与资源，核对逐项迁入结果，抽查文件、名称、来源对应关系与可见范围，并确认库内取用说明实际存在、指向正确资源。返回实际库位置或经核实的入口，简述如何找、如何用、已入库与未完成范围；仅有聊天方案、外部链接或本地文件时，明确尚未完成 Virse 入库。涉及画布索引或展示时按需补读 `virse-canvas` 的对应参考并核对真实显示。

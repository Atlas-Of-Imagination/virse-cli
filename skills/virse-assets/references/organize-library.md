# 资产库整理

## 确定范围，理解资料与使用习惯

先明确个人或团队空间、整库或指定目录、包含哪些资源，以及不动的目录、名称和现有结构。已有信息沿用，只补问影响整理的缺口。按[查找与读取](browse.md)盘点范围内全部目录与资源，核对分页和截断；未读完不称完整盘点。按需查看真实内容，了解项目、常用素材、历史资料与待确认项，不能仅凭名称判断归属。

画布也是资源目录中的文件。判断项目时，可补读 `virse-canvas` 的理解与取材参考查看内部内容及素材关系；整理其目录归属时保留内部节点、配置与连线。结合用户平时怎样找资料、哪些经常复用，理解现有分类中值得保留的部分。

## 保存选择与详细方案

正式出方案前，询问：“要不要先保存一份当前状态记录？之后可以用来核对变化，必要时协助撤回可恢复的改动。”已有选择沿用；拒绝也继续规划，不擅自保存状态。

同意后，将实际状态保存为本地持久记录，告知路径和覆盖范围：保留本次批次、后端与执行身份、组织、范围、读取时间，以及资源稳定 ID、原父目录和名称、实际可读的置顶收藏状态与目录顺序；缺项标明。它是整理记录，不是原件备份或整库还原点。[资源变化](resource-changes.md)中的完整快照只用作核对依据；独立子树不能冒充一致快照。

结合盘点主动推荐适合这个库的方案，说明理由与取舍，必要时给备选，让用户在草案上选择、组合和修改。

| 整理参考 | 适合的查找习惯 |
| --- | --- |
| 项目或客户 | 画布、输入素材、尝试与交付围绕同一工作使用 |
| 主题或对象 | 经常跨项目寻找人物、产品、场景或材质 |
| 素材类型 | 先按图片、视频、3D、文档等进入制作 |
| 用途或风格 | 按广告、社媒等用途，或某种视觉感觉取材 |
| 创作阶段或选用状态 | 区分原始、候选、已选、已交付与历史资料 |
| 时间、批次或来源 | 经常按拍摄、生成、导入批次或提供者回找 |

上层优先回应用户最常用的找法，下层在确有需要时细分；可组合嵌套，不预设统一目录树或层数。跨项目常用素材可保留稳定位置并收藏置顶，也可按用户需要复制到通用库或项目；独立副本不是同步引用。

完整方案交代：范围与保留项、目标目录树及每部分放什么和怎么找、分类命名规则、现有资源的去向与移动/复制/保留策略、常用素材的取用方式、待确认项。用真实资源展示整理后路径，并让用户尝试找回常用内容。疑似重复、过时或用途不明的内容列出供选择；不凭同名或缩略图直接合并删除。用户敲定方案后才执行；已有确认范围沿用。

## 执行、核对与有条件撤回

执行前核对现状与期间变化，按[整理与归档](organize.md)处理确认的对象；冲突项先对齐，不覆盖他人后续修改。逐项核对实际结果；已选择保存现状时，持久记录操作顺序、原请求与键、逐项回执、执行后状态和新建资源真实 ID。未知受理按执行与恢复（`virse-base/references/contracts/execution.md`）对账，不换键盲目重做。

完成后返回实际目录位置、变化摘要与待确认项，并说明记录路径及本次可撤回范围。用户要求撤回时，按记录核对当前状态，逆序补偿已确认成功且仍符合条件的操作。改名移回需原名称和目录仍可用；新副本或目录须确认本次身份及后续内容，才能移入回收站。后续改动、权限变化或证据不足的项保留供用户决定；移入回收站及恢复按[回收与清理](recycle.md)核对实际位置。

当前 CLI 没有整批撤回，状态记录不保证并发下原子恢复；永久删除无法由此恢复。记录缺失或用户未保存时，先核对现有证据和可恢复范围，不承诺一键还原。

方法溯源，需核实时再读：[Bynder 资产库审计](https://support.bynder.com/hc/en-us/articles/21213841926418-Guide-to-Auditing-your-DAM)、[Adobe 目录组织](https://experienceleague.adobe.com/en/perspectives/folder-structure-best-practices-for-aem-assets)、[PARA](https://fortelabs.com/blog/para/)、[Johnny.Decimal 分类](https://johnnydecimal.com/documentation/areas-and-categories)。借鉴其选择依据，以 Virse 当前实际能力执行。

# 目标、输入依据与效果迭代

## 明确保留与改变

把任务落到要交付的作品、用途与可观察要求。区分必须保持的主体、文字、关系或风格，以及这次允许改变的部分。优先利用用户已给出的要求；缺少决定性信息才补问需求，不固定要求每次补齐一份完整 brief。生成前仍按[选型确认](models-and-submit.md#提交前确认)处理；已确认或已授权范围内的迭代不重复询问。

先检查已有素材能否复用。只需排版或改节点名称时做结构操作；只需去背景或放大时选对应处理；需要改变画面内容时选择合适编辑方式；已有工具确实适合且输入合同明确时可固定工具产物执行。精确管理、指定模型或工具产物的任务优先由 CLI 直做；需要围绕画布材料连续创作、组合多步操作与反馈时，可主动选择 Composer（`virse-composer`）。复杂程度本身不是委派理由，也不要因为缺一个参数就制作新工具。

混合任务由外部 Agent 统筹：从宿主已有且获准使用的资料、其他应用内容和画布材料中提取创作依据，在 Virse 完成适合的环节，再结合宿主能力完成全部交付。把必要事实、保留项与参考作用转为明确输入；本地路径或外部链接本身不证明材料已传入，媒体按实际支持的上传或引用合同处理。

只委派范围明确的画布子任务，交代材料、保留项和验收要求，并检查全部交付。同一目标不同时通过 CLI 和 Composer 重复执行。沿用已有相关会话，明确引用的元素不等于整画布上下文；委派不保证解决排版或未公开功能，受理不明先查原节点 get/history/watch，不重发。

## 复用原图与任务依据

用户要求“看原图配置，改提示词继续生成”时，先读明确的节点及相关任务：

```bash
virse --org "$ORG" --canvas "$CANVAS" --json canvas element get "$ELEMENT"
virse --org "$ORG" --canvas "$CANVAS" --json generation list --element "$ELEMENT" --offset 0 --limit 50
virse --org "$ORG" --canvas "$CANVAS" --json generation get "$TASK"
```

分别整理实际读到的当前模型配置、prompt、参考、参数、资产与任务身份，标明来源。节点当前 `generation.config` 不保证等于当时成功作品的完整输入；任务也没有保证齐全的历史输入字段。上传图、历史版本或供应商最终 prompt 不能凭图像内容反推为确定事实。

缺失的信息影响本次创作时，说明缺项并取得用户的新要求，或在原授权范围内提出有依据的新输入。不要把自己分析出的描述写成“原提示词”。参考从其真实节点身份取得，不能把 asset ID 填入要求 element ID 的 flag。

## 选择参考与输出目标

为每个参考说明作用：例如保留主体、借用构图、颜色或气氛，而不是将全部画布节点机械加入。按实际支持的顺序和数量提交，检查用户要求与模型可用能力是否匹配；模型参数与角色输入来自运行时合同。

默认按用户的保存意图选择新节点或原节点。明确“继续生成并保持节点位置”时，先记录 layout，本次提供完整输入并用 `--target-element` 指向原节点，执行后读回位置与结果。它不自动复用旧输入，不保证图片内部构图或 3D 姿态严格不变。用户要比较方案时保留明确的基准，不用一次覆盖掩盖前后差异。

## 检查真实作品

取得任务实际产物后，使用[文件交付](shared/contracts/delivery.md)允许的预览或原件及宿主实际可用的查看能力检查。结构数据不替代图片观察，文件存在不替代内容检查，模型自己宣称完成也不替代真实产物。

检查围绕本次目标：主体和约束是否保留、画面层次与构图是否适合用途、文字是否准确可读、参考特征是否被正确采用，以及有没有明显瑕疵。比较时对照同一基准和要求，不将个人风格偏好冒充用户要求。视频、3D 与文本只对实际能查看的部分下结论。

## 针对具体问题迭代

说清“观察到的问题 → 为什么影响目标 → 本次改什么 → 仍需保留什么”。选择足以解决问题的输入或操作，尽量避免无关改动，使前后差异可解释；并非所有问题都需要换模型或重做整张作品。

改变输入后建立新的创作请求和新键，保存其参考与结果关联。若只是网络丢响应，走[生成任务合同](shared/contracts/generation.md)恢复原受理，不将未知状态误当作一次质量失败。根据真实产物与用户反馈继续，交付时说明已验证的要求和仍无法确认的部分。

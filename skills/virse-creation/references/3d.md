# 3D 生成的实际边界

## 文本与图片建模

按文本生成模型：

```bash
virse --org "$ORG" --canvas "$CANVAS" --json generation 3d --model "$MODEL" --prompt "$PROMPT" --idempotency-key "$KEY" --wait
```

按已有图片节点作为参考建模时：

```bash
virse --org "$ORG" --canvas "$CANVAS" --json generation 3d --model "$MODEL" --reference "$IMAGE_ELEMENT" --idempotency-key "$KEY" --wait
```

有参考时可省略 prompt；没有参考时须提供文字。`model3d` 是 `3d` 的命令别名。参考是否为可用图片、支持几张或哪种参数由模型与后端判断；不保证多视图一致或特定重建精度。快捷命令提交一个 three_d_generate 输出，目标与恢复见[生成任务合同](shared/contracts/generation.md)。

## 检查真实模型与未具备的环节

先确认输出资产与节点，再取得获准的实际模型文件。宿主确有查看能力时检查可观察的形体、比例与用途要求；静态预览不能证明背面、内部结构、拓扑或可制造性，不能只凭成功状态下结论。

“3D 选视角，渲染参考后生成”需要独立的相机与渲染合同。当前 3d 命令只有建模，不提供设置内部相机、材质灯光、动作时刻、截图、拍摄录像或组件编辑的专用入口。通用 submit 必须有运行时实际声明的对应 operation 才能执行；不能用节点位置或 Composer 委派冒充这些环节。用户已有外部渲染参考时，可在其真实可用和获授权的范围内继续后续创作。

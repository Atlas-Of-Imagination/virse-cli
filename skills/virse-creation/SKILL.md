# 创作与修改作品

<!-- virse:background:start -->
Virse 是 AI native 的创作系统，以画布连接想法、素材、审美、工具、模型与创作过程，支持图片、视频、3D 与文本创作。资源目录管理素材与归属，画布组织输入、执行和结果。

结合宿主实际可用、用户已授权的本地资料与其他应用上下文，理解创作目标、参考材料和约束。在 Virse 中组织、创作与迭代，将产物整合回用户的完整任务。

手动连线把内容作为引用接到目标创作框，供其衍生新内容，不表示任意关联或阅读顺序。审美复用视觉方向，智能工具复用创作方法；Composer 是画布内有独立会话的创作家。按目标选择 CLI 直接操作或委派 Composer，能力和权限以实际合同为准。

面对创作任务，你是一位与用户共同推进作品的创作家。理解作品的用途与表达，结合已有素材、审美和约束作出有依据的创作选择；目标明确时主动准备和推进，首次生成前确认模型与关键参数。用户已明确授权自主选择或此前已有约定时，按其范围执行。查看真实作品，针对具体问题迭代，尊重用户的方向与保留项。查询、整理和权限任务按原目标完成。

用户给定后端时，在首条远端命令前设置 `VIRSE_BACKEND_URL`；profile 不保存后端。只加载当前任务所需的参考，已读的相同合同无需重复；链接不会自动加载内容。
<!-- virse:background:end -->

## 从目标到作品

先明确交付用途、必须保留的内容与本次要改变什么，利用用户已给出的宿主材料和画布上下文。已有要求足够时直接准备，不固定做开场访谈；首次生成前简短推荐当前可用、目录靠前且适合任务的模型和关键参数，等用户确认后提交。用户已明确授权自主选择或已约定配置时，按其范围执行，不重复询问。具体选型与确认方式见[模型与提交方式](references/models-and-submit.md)。

按目标选择直接生成、图片处理或适用的已有工具；只有需要新的执行逻辑才进入工具制作。精确管理、指定模型或工具产物时优先 CLI 直做；需要围绕画布材料连续创作、组合多步操作与反馈时，可主动选择 Composer（`virse-composer`），不以用户点名为前提，也不因任务复杂就全部委派。混合任务仍由外部 Agent 统筹并验收全部交付。

完成选型确认或已有相应授权后，可用下面的普通生图短路径。示例变量来自当前任务与真实查询；`MODEL` 使用当前可用 model_key，`KEY` 为本次输入固定保存的幂等键。

```bash
virse --org "$ORG" --json model list --mode image
virse --org "$ORG" --canvas "$CANVAS" --json generation image --model "$MODEL" --prompt "$PROMPT" --idempotency-key "$KEY" --wait
```

模型已知且仍适用时无需重复列全目录。未知操作或特殊输入才查询 `generation operations`；参数不清楚时查对应命令 help。快捷命令没有通用 `--aesthetic`，取用审美必须有当前消费方真实支持的输入合同。

执行后核对 task 和逐输出状态，取得实际内容并按用户要求检查。发现问题时说清具体差异、这次改变和保留项；改变输入是新创作，使用新键。查找原受理结果与按原输入、原键恢复是另一条路径，不能混同为效果迭代。

## 完成判断

记录本次目标、参考及关键输入、task ID、逐输出状态、节点和资产身份；需要文件交付时核对实际文件。`get` 退出 0 只证明读取成功，`succeeded` 也不能证明文字、构图、审美或品牌要求已满足。无法查看某种产物时说明哪些质量尚未验证。

当前节点配置不保证完整历史 prompt；指定输出节点不自动恢复原模型或输入。画布显示位置不等于图内主体位置，布局尺寸不等于模型输出分辨率。没有实际开放合同的 3D 相机、渲染和截图能力不能由通用 submit 或 Composer 委派补成已支持。

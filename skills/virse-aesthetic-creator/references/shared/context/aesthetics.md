# 审美身份与普通取用

## 区分资源、审美和快照

审美把一组参考图表达的视觉方向保存为可复用条件。构建结果是系统分析图集得到的审美指导，与名称、展示描述分开；描述不会自动成为模型指令。它用于受支持的创作与搜索，不等于把图集逐张作为普通图片输入。本次要创作什么、必须保留什么，仍由当前任务说明。

资源目录中的审美节点使用 `dentry_id` 标识位置与访问关系，其目标是 `style_id`；画布节点、审美草稿和测试快照还各有自己的身份。不能把资源 ID、画布节点 ID 或会话 ID 直接当作 style ID。

普通使用先明确用途与希望保持的视觉特征，再查真实对象、可见内容与资格。可查看不等于可编辑，也不等于任意模型都接受该审美；具体生成 operation、工具 Schema 或 Composer 请求的受支持字段决定如何传入。

## 读取普通详情

已有真实 style ID 时：

```bash
virse aesthetic call details --data '{"style_ids":["11111111-1111-4111-8111-111111111111"]}' --json
```

示例 UUID 替换成当前对象的真实 UUID。有画布上下文时可在 JSON 中补 `"space_id":"<canvas-id>"`，用于核对画布关系；全局 `--org/--canvas` 不会替你补进 `call` 的请求。

成功返回包含 `styles` 与 `denied_ids`。只使用实际返回的对象；`denied_ids` 表示没有返回，不能据此区分无权与不存在。详情可包含名称、用户展示描述、参考图 `images`、相关 `spaces`、状态和 `can_view/can_edit`。检查具体字段是否实际存在，不把缺少展示描述解释成没有视觉条件。

普通详情隐藏内部 `aesthetic_summary`，非用户填写的历史描述也不会作为普通描述展示；**只为查看、选择或使用审美，不要求读作者 `context`**。创建/训练的回执和公开运行状态也不能当作作者正文。

## 在创作中使用

先读取当前生成 operation 或确定工具 artifact 的输入 Schema，确认接受审美的字段与引用格式，再传入该接口要求的 style、资源或快照身份；不要把展示描述拼成内部正文，或为了取用发起训练、替换参考图。

已有审美可能为正式资源、尚未入目录的作者草稿，或特定画布内的副本。引用资格由服务端结合当前组织、画布与资源权限校验；官方模板的只读可见也不授予编辑权。实际生成后查看产物，确认视觉效果，不能仅凭绑定成功保证审美被模型以相同方式体现。

放入画布时形成保存当时内容的审美副本；源资源重新构建、改名或撤回分享，不会自动覆盖该副本。画布副本随画布权限供协作者查看和使用，不自动加入各自的资产管理。要更新某次创作的视觉条件，先确认使用的是源资源、画布副本还是测试快照，再按对应合同修改或重新取用。

## 转入作者工作

用户要改变参考材料、审美正文或训练结果时，进入审美制作职责。正式资源编辑须提供与 style 匹配的 `dentry_id`，不能省掉它降级为草稿鉴权；未保存草稿通常要求直接创建者。画布内部副本按其真实所属画布的编辑权限核对。

作者草稿会话中的 `revision` 是会话修订号，测试 `snapshot` 是冻结的一份审美内容；二者不构成工具式正式 release。训练完成不等于保存，保存草稿不等于已经出现在目标资源目录。

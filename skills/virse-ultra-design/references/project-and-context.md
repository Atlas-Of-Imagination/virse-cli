# 项目与 Context

## 接住输入，主动带领

从当前目标与已给材料开始，持续说明什么 Context 有帮助、会用于哪个判断。按项目举少量贴切例子：产品照片与参数、已有作品、喜欢或不喜欢的参考、品牌资料、脚本、客户反馈、本地文件夹、平台链接、Virse 画布或资源目录。用户可以随时补充，只有一句想法也能开始；材料未整理时由宿主梳理。

开场可这样表达，随已有上下文缩短或调整：“你想完成什么？想法、图片、文件、其他平台链接和已有 Virse 资料都可以给我，不用先整理。我先看已有内容，帮你推荐做法；只有一个方向也能开始，制作中可以继续补。”

先读用户提供且有权访问的内容，再提关键缺口，避免固定长问卷。已有 Context 足够时先给可调整的方案或作品；用户不确定时，提供有依据的推荐和取舍，帮助他作出选择。每次获得重要材料后，说明理解了什么、怎么用、建议接着做什么。用户可以跳过暂不需要的品牌、趋势、研究或其他模块。

## 读取与汇集

按来源使用宿主实际可用的能力：本地读取限定在用户指定或任务已授权范围；外部资料通过可用连接器、MCP、CLI 等读取。缺连接时具体引导连接、登录或提供可读导出；链接标题和访问失败均不代替正文。平台原件、预览与导出表示分别标清，Virse 不支持的原生工程保留原位置或可用入口，按实际能力制作可查看的表示。

理解资料中的事实、用户要求、创意参考与待验证判断。为参考明确作用，例如产品图保留外形，另一张只借光线，历史作品提供已认可的表达；不把全部材料机械塞进每个任务。来源冲突影响当前方向时指出具体分歧并推荐处理，未知产品卖点或历史 prompt 保持未知。

实际导入使用 `virse-assets`，取画布内容用 `virse-canvas` 的 `references/read-select.md`。读取真实内容后再判断，按需要汇入项目，保留可追溯的来源与适用范围。

## 敲定工作现场与推进范围

明确开始项目时，沿用已确认的个人或团队空间和项目位置；缺少空间信息才走连接与空间选择。建议项目名称和保存位置，与用户敲定后创建或沿用文件夹；仅讨论方案时按当前请求处理。目录操作用 `virse-assets`，创建画布取 `virse-canvas` 的 `references/edit-graph.md`；读回真实身份并返回项目入口。创建结果不明先对账，不能盲目再建一份。

结合任务推荐怎样使用画布，与用户确定数量、分区和展示方式。材料、方案、作品和讨论可共处一张画布，内容增长或交付需要时再调整。沿用现有画布与保留项，跨来源材料先取用所需内容，不因引用某画布就迁移整个原项目。

方案围绕本次用途、交付、必须保留的内容、可探索范围、当前缺口与优先事项展开。用户可以陪着定方向，也可以授权自主推进；已有决定直接沿用。首次生成前，缺少适用授权时由 `virse-creation` 推荐当前可用且适合任务的高质量模型与关键配置并确认；授权范围内制作和迭代直接推进，超出范围再讨论。

## 保留主线，接续建设

在项目可读的说明或画布中保留目标、采用方向、关键依据、相关成果和待选事项，随重要决定更新。让用户知道当前推进什么、已得到什么、接下来最有价值的动作是什么；新 Context 改变判断时说明影响，更新相关作品和依据。

本地只保留继续执行必需的项目位置、真实对象 ID、任务或会话身份、原始 brief 与待核对项；与用户成品分开，不把内部日志塞进最终指南。长任务接续先找回这些信息，再读本轮所需内容并核对可能变化的对象，无需重新读取整套资料或重建项目。

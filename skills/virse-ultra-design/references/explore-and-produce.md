# 探索与并行制作

## 快速形成可判断的成果

结合用途与实际材料，主动推荐最值得先验证的创意问题和做法。方向可以在概念、情境、构图、叙事或媒介表达上产生有意义的差异；范围与数量随项目决定，已明确方向就接着制作。需要研究或找参考时，取 `virse-creation` 的 `references/inspiration-exploration.md`，用户指定的来源优先，依据实际需要补充。

选择足以支持当前判断的成果：真实概念图、关键镜头、短片段、文本内容、3D 试作或其他适合的作品。说明它验证什么、确定后怎样延展；在实际作品中验证构想，再决定深入或调整。保留创意选择的空间，按用户目标形成表达，不套固定风格、方向数或媒介套餐。

图片方法按需取 `virse-image-craft`，开始动态表达时取 `virse-video-craft`，执行用 `virse-creation`。3D、文档或外部工程结合宿主真实能力处理，工具未开放的操作不能通过委派变成已支持。

## 主动并行，保持一致

识别依赖关系后尽早启动可独立的工作：多个方向探索、独立素材准备、内容研究、不同交付制作等可并行；需要选定方向或前序素材的部分，在依据明确后接续。方案中说清各任务的目标、输入、产物及依赖，让用户知道哪些会同时推进。宿主持续推进自己负责的独立工作、整合回收和用户交流；避免把同一目标同时交给 Composer 又重复生成。

多个独立方向或子任务适合画布内连续创作时，优先主动安排 Composer 分工；精确管理和已指定模型、工具产物的执行保留 CLI 短路径。不同目标用独立节点与会话，已有承担该目标的会话直接沿用；同一画布可约定独立区域，是否拆画布按项目方案处理。交代各自可改的范围、共同保留项和产物位置，宿主负责合并涉及共同对象的修改，减少相互覆盖。

规划与制作遵循已有模型、关键配置、数量和费用授权；授权未明确时先在宿主准备建议，不提前发送可能生成的任务。分批数量与并行程度按任务、资源和实际平台状态调整，不承诺全部任务同时运行或固定完成时间。

## 把 Context 变成具体交办

读取 `virse-composer`，按当前动作取节点、消息和观察参考。发送前整理本次需要的 brief：

- 子任务目标、用途及希望回答的创意问题。
- 用户已确认的事实、参考分工、保留项、可改变范围。
- 实际可用的材料节点引用与必要内容；本地或外部素材先按合同转成可用输入。
- 已确认的模型与配置，或自主选择的明确范围。
- 操作区域、需要回传的实际作品与身份、验收要求及关键缺项。

传入的是具体内容与引用，不是另一份 Skill 的名字；Composer 不自动继承宿主对话、本地路径、外部账号或整张画布。只传任务必需且获准传入的资料。先 `composer create` 或取已有节点，再 `send`；需要并行时分别提交、保存 run/turn 身份并观察，创建节点本身不启动创作。

## 比较、推荐与继续

按实际回合和产物检查结果，查看真实图片、视频或可访问内容；需要时补文件交付能力。对照目标说明具体优势、问题、差异与建议，不只给用户扔一组结果。把可查看作品和必要比较整理回项目画布，形成实际成果时返回核实过的入口，让用户能自然选择、组合或补 Context。

把用户反馈转换为“本次改变什么、为什么、保留什么”，保留基准与采用依据。上一回合结束后向原 Composer 再发送才是继续会话；独立的后续任务可另行安排。运行中新增信息先保存，按当前支持的停止或完成后继续方式处理，不假定有消息追加队列。

回合完成、命令成功与作品通过分别判断。受理不明先查同一节点的状态和历史，不盲目重发；等待超时不等于远端停止。新生成与费用超出约定时再确认，范围内迭代继续执行。

# 参数

## 先选路径，再查可用控制

用创作目标筛选能力，再读取当前模型与 operation 的真实 schema。Virse 产品模式、模型能力、输入角色和参数共同决定请求，不能只按模型名称或厂商宣传判断支持。

运行时模型目录的 `generation_capabilities` 用于判断当前支持的产品任务。模型详情与 `generation operations` 用于确认输入媒体、顺序、角色、数量、参数及组合限制。源码里有某入口不证明当前后端或账号能用，厂商有某功能也不证明 Virse 已接入。

Virse 的 video 快捷入口通过 `--model`、`--prompt`、有序 `--reference` 与 `--parameters`／`--parameters-file` 传递输入，没有通用 `--task-mode` 或 `--first-frame` flag。已声明的服务端模式可以由参数 JSON 表达；具体字段和角色绑定必须来自运行时合同，不能因没有快捷 flag 就断言 CLI 无法选模式。需要特殊角色或快捷入口不能表达的组合时，按 `virse-creation` 读取通用操作合同，不自行造字段。

## 让参数服务于创作判断

| 控制 | 什么时候有用 | 与输入和效果的耦合 |
| --- | --- | --- |
| 时长 | 保证动作、反应、展示停留有足够时间 | 受模型、模式、音频和输出配置限制；更长也可能增加身份漂移和事件遗漏 |
| 宽高比 | 适配投放、屏幕、构图与动作方向 | 与首尾帧和参考比例相互影响；横图做竖屏可能裁切或补出新内容 |
| 分辨率 | 满足交付尺寸、文字或细节观看需求 | 受模式、时长和模型限制；高分辨率不能补救错误结构、变形或错误台词 |
| 帧率 | 满足播放、交付或运动呈现要求 | 只在明确暴露时设置；高帧率不等于慢动作，后期插帧也不等于模型原生生成更多正确细节 |
| seed | 在支持时帮助比较相近条件或复现请求 | 不保证跨模型、跨后端配置或改动参数后的确定性；相同 seed 不保证身份保持 |
| 音频开关与相关配置 | 决定是否生成音轨，或启用已声明的音频输入 | 支持有声、音频参考、保留原音、音色和口型是不同能力，分别核对 |
| 参考强度、运动强度等 | 只有 schema 暴露且语义明确时，平衡遵循与变化 | 不同家族含义不同；不能默认数值越高越好，也不能把文字形容当作真实参数 |
| 相机或动作控制 | 需要较明确轨迹且模型提供专门入口时 | 文本运镜提示、视频动作参考与结构化控制不是同一能力 |

画布节点布局尺寸不是模型输出分辨率；prompt 中写某个尺寸也不等于真实配置已设置。未暴露的帧率、镜头参数、音频或参考控制，不补成可用参数。

## 处理组合约束

先核对决定模式的输入，再核对交付参数。常见冲突包括：当前模式不接收视频、首尾帧缺一端、参考顺序错误、所选比例不支持、某分辨率不能搭配目标时长、某声音配置只在特定路径有效。

参数报错时先修输入与 schema；画面效果差时先判断参考、动作和时长是否合理。不要把每个质量问题都归因于分辨率，也不要为提升画质自行更换用户指定的主体、路径或模型。

首次生成前按 `virse-creation` 核对已有模型与参数约定或明确自主授权。偏好、历史曾用过的配置或一次确认不自动扩大授权范围；需要改变关键选择且不在已有范围内时，说明推荐及理由并确认。

# 节奏与声音

## 把时间留给观众要看清的东西

先按用途安排动作密度。结构演示需要看清接触和变化，人物表演需要反应与停顿，抽象动画可以靠运动幅度、重复和留白形成节奏。短片不必都有起承转合；一个清楚的变化也可成立。

将重点分配到相对阶段：“先停留看清产品，随后展开，最后留出展示时间”。需要更明确时可写大致时间，例如“前段缓慢靠近，中段完成按钮按压，末段停留看清灯亮”。时间码能表达约束意图，通常不能保证逐帧兑现、准确切镜或音画事件精确落点。

检查时长能否容纳内容：进入画面、停步、说话、转身和离开都需要时间。事件被省略或加速时，先减少事件、缩小动作或在能力允许时增加时长。不能只把“完整展示所有过程”再强调一遍。关键时刻必须精确对齐时，需要实际剪辑或专门控制，不能由粗略时间码代替。

## 先区分声音能力

| 用户想要什么 | 需要确认的能力 | prompt 写什么 |
| --- | --- | --- |
| 自动生成声音 | 所选视频模型是否输出音轨、是否有音频开关 | 环境、对白、音乐和事件声的优先关系 |
| 上传音频作参考 | 接口是否接收音频，以及用于节奏、语音、音色还是原音轨 | 明确借用作用；不把“参考”视为原样嵌入 |
| 保留原音 | 编辑或续写是否明确保留音轨，还是重新生成 | 指定保留内容，并实际听取输出比较 |
| 指定音色 | 是否提供音色控制或支持身份保持 | 声音特征和表达方式；不承诺凭形容词精确克隆 |
| 对白或旁白 | 是否支持语音、所需语言和说话人控制 | 谁说什么、语速、情绪、对白发生在何处 |
| 口型同步 | 是否支持以音频驱动口型或生成同步对白 | 说话人、目标对白或已提供音频，避免多人身份混淆 |
| BGM | 是否生成或接收音乐 | 风格、速度感、起落与混音重点，不写成屏内物体发声 |
| SFX 与环境声 | 是否生成事件声和环境声 | 声源、触发动作、先后与距离感 |

这些能力可以独立存在。支持有声视频不代表支持上传音频，支持音频参考不代表保留原音，生成对白不代表能精确复现指定音色，视频参考也不代表会复用其音轨。

## 让声音和动作互相解释

对白写清说话人、台词与表达，不用情绪词覆盖台词本身。人物只需要轻微反应时，不擅自添加独白。对话量应适应时长；短时间塞入长句容易导致抢话、赶语速或截断。

环境声负责空间感，事件声负责动作，音乐负责整体节奏。以用途决定哪一层突出，避免每一层都“强烈”。例如产品演示可以写：

> 安静室内底噪，按钮按下时一声清脆轻响，灯亮起没有额外夸张音效；无对白，声音保持克制，让观众注意按压和点亮的关系。

动画可以写：

> 圆点落地时出现短促柔和的弹跳声，连续三次弹跳的间隔逐渐拉长，最后安静停住；背景音乐不盖过弹跳声。

需要跟已有音乐卡点时，先查是否有真正的节奏或音频驱动。仅写“随音乐节拍”不能保证帧级同步。若必须精确，按实际音轨安排动作，再通过后期调整；不要声称写了节拍描述就已完成卡点。

实际验收时正常速度播放并听音，检查台词是否完整、说话人是否正确、口型是否同步、事件声是否对上动作、音轨是否突然中断。静音抽帧无法验收声音。

# 从画布发现可复用任务

用户希望把复杂画布里的创作方法沉淀成智能工具时，主动发现并推荐值得复用的任务，再将认可的方法做成可测试的原生包。不要要求用户先找出流程；指定区域只是可选输入。

## 浏览与判断

按需读取 `virse-canvas`。已有目标节点或分组就直接浏览；未指定区域时先浏览整体，理解分区、作品与关系，再沿候选深入真实素材、可读配置、引用和文字。需要查资源详情时读取 `virse-assets`。不能只看缩略图或节点名称就归纳方法。

寻找输入能替换、方法值得固定、输出可观察的任务。结合画布内重复出现的操作、相近任务的变体、明确的处理说明及用户用途判断价值；一次出现的任务也可能值得复用。说明哪些判断来自画布证据，哪些需要用户补充。单一画布只能证明画布内的重复，不能证明用户全历史的常用频率。

创作引用边表示素材引用，不自动构成可执行工作流。只使用实际可读的 prompt、配置和说明；不能从成品猜造原 prompt、完整历史流程或工具源码。证据不足时，可以提出新的可复用方法或候选优化，但要明确这是建议，并说明缺少什么。

## 推荐与认领

主动推荐值得沉淀的任务，关联具体节点或分组，讲清用途、可替换输入、固定方法、预期输出、复用价值和缺失信息。候选的数量与表达按画布内容决定，不把整张画布机械拆成工具。

让用户认领或调整候选及方法后制作；已有认可或明确自主授权就沿用对应范围。只追问影响执行与验收的缺口，不能用一串问题代替浏览。优化候选时保留用户原有目标和作品中的关键特征。

## 制作、测试与回画布

按[原生包与校验](native-package.md)把方法落实到输入、说明及必要依赖；不能把画布链接当作运行环境必然可读的完整方法。需要新创作或效果判断时按需读取 `virse-creation`，沿用现有模型与关键参数授权；超出范围先确认。

按[产物测试与发布](artifact-lifecycle.md)构建并固定 artifact，用真实输入运行、查看实际产物，分别判断运行完成与输出符合任务。修改包后重新构建测试。用户要求发布时才发布对应范围。

复用测试已创建的工具节点，或按运行合同（`virse-base/references/contracts/tool-run.md`）将已测试的固定 artifact 放到原工作画布，核对真实绑定。将任务总结、输入使用说明和实际测试结果放在对应素材附近，保留已有作品与关系；返回实际画布或节点链接。清楚区分只完成总结、已制作未测试、已测试及已发布，不把校验或 build 成功当成效果验收。

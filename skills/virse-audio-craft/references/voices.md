# 音色

## 音色从哪里来

音色有三种来源，能力互不替代，按所选模型与任务的声明选择：

| 来源 | 在目录里的形态 | 适合什么情况 |
| --- | --- | --- |
| 预置音色 | 参数类型 `voice`，值为音色 id 数组 | 需要稳定、可复用的现成声音 |
| 声音参考 | 音频槽位，如 `voice_reference`、`reference_audios` | 要借用某段录音的声音特征，且模型声明支持 |
| 换声目标 | `voice_change` 任务的 `voice` 参数 | 已有录音，只改说话人的音色 |

用户提供录音时，先确认获准使用这段声音，且用途符合授权范围；借用他人声音的边界由用户与所在场景决定，不能因为模型支持就默认可用。

## 查预置音色

```bash
virse --json voices list --model "$MODEL"
```

返回该模型的预置音色列表，每项有 `id`、中英文名称、性别、语言、标签与试听地址。模型不带音色参数时返回 404；返回空列表表示该模型的音色还未整理，此时提交任何音色都会被拒绝，不能编造 id，也不要从其他模型的列表借用。

按用途、语言、性别、年龄感与语气挑选，有试听地址时实际听过再推荐，名称和标签只能帮助初筛。用户指定了某个音色时核对它在当前模型列表里；不在时说明并给出相近候选，不自行替换。

## 提交音色

`parameters.voice` 恒为数组，长度等于该任务生效定义的 `count`：单人 `{"voice":["$VOICE"]}`；双人对白 `{"voice":["$VOICE_1","$VOICE_2"]}`，下标 0 对应 `Speaker 1`，下标 1 对应 `Speaker 2`，两个 id 允许相同。同一模型在不同任务下 `count` 可能不同，以 `audio_modes[任务].param_overrides` 与模型级定义合并后的结果为准。

参数带 `excludes_inputs` 时，列出的槽位有输入就不能再给预置音色，例如某些模型提供参考图时不能同时指定音色；同时提交会被拒绝，按用户目标选一种。

## 双人对白配音色

两个声音要容易区分：性别、音高、语速或气质至少有一项明显不同。两个 id 相同时，靠台词本身区分说话人，听感上可能难以辨认，交付前说明。

## 换声

`voice_change` 保留源音频的说话内容、节奏与语气，替换音色。源录音的噪音、混响、多人重叠会影响结果；模型声明了降噪参数时按需开启。源音频时长受槽位 `max_seconds_each` 限制，超出时先裁剪或分段，不依赖供应商静默截断。

换声不改台词、不翻译；要改内容就用 `tts` 重新生成。

## 声音参考

声音参考借的是声音特征，不保证逐字复现原声的口音、气息或情绪。参考录音宜干净、单人、无伴奏，时长落在槽位声明的上下限内；多段参考应来自同一个人、风格相近。参考能否与预置音色、参考图同用，看模型级 `input_exclusions` 与参数的 `excludes_inputs`。
